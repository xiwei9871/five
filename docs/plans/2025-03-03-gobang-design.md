# 五子棋Web游戏 - 设计文档

**项目类型：** 休闲娱乐产品
**创建日期：** 2025-03-03
**技术栈：** Vue 3 + Vite + Pinia + Naive UI + Capacitor

---

## 1. 项目概述

开发一款面向休闲用户的五子棋Web游戏，支持本地双人对战和人机对战模式，具备简洁清爽的UI设计和AI对战能力。最终可打包为Android应用。

### 核心功能
- 15×15标准五子棋棋盘
- 本地双人对战模式
- 人机对战模式（简单/中等/困难）
- 悔棋功能
- 对局历史记录
- 本地存档功能

### 目标用户
- 休闲娱乐的普通用户
- 需要简洁清爽的游戏体验
- 支持桌面端浏览器和Android设备

## 3. 核心组件设计

### 3.1 Board.vue（棋盘组件）

**职责：**
- 渲染15×15的棋盘网格
- 处理点击落子事件
- 显示棋子（黑白棋）
- 显示最后落子标记
- 显示获胜连线

**Props：**
```javascript
{
  boardState: Array(15).fill(Array(15)),  // 棋盘状态
  lastMove: { x: number, y: number },     // 最后一步位置
  winningLine: Array<{x, y}>              // 获胜连线
```

**Events：**
- `place-piece(x, y)` - 落子事件

**关键特性：**
- 使用DOM渲染棋盘（便于样式控制）
- 响应式适配不同屏幕
- 动画效果（落子、获胜高亮）

## 4. 数据流设计

### 4.1 游戏状态结构

```javascript
// stores/gameStore.js
{
  // 棋盘状态 15x15，0=空，1=黑，2=白
  board: Array(15).fill(null).map(() => Array(15).fill(0)),

  // 游戏设置
  gameMode: 'pvp' | 'pve',        // 双人/人机
  aiDifficulty: 'easy' | 'medium' | 'hard',
  playerColor: 'black' | 'white', // 玩家执子（人机模式）

  // 游戏状态
  currentPlayer: 'black' | 'white',
  gameStatus: 'ready' | 'playing' | 'finished',
  winner: null | 'black' | 'white' | 'draw',

  // 历史记录
  moveHistory: [
    { x: 7, y: 7, player: 'black', timestamp: Date }
  ],

  // 最后一步（用于高亮显示）
  lastMove: { x: 7, y: 7 },
  winningLine: null  // 获胜的五子连线
}
```

### 4.2 数据流向

```
用户点击棋盘
    ↓
Board.vue 发出 place-piece 事件
    ↓
useGameRules 验证落子合法性
    ↓
更新 board 状态
    ↓
检查获胜条件
    ↓
┌─────────────┬──────────────────┐
│   未获胜     │    已获胜/平局     │
│             │                   │
↓             ↓                   ↓
切换玩家    记录历史          更新gameStatus
    ↓             ↓                   ↓
人机模式？    更新lastMove      显示获胜信息
    ↓             ↓
是 → 触发AI    保存到LocalStorage
↓
AI计算落子
↓
执行AI落子
```

## 5. AI算法设计

### 5.1 AI难度分级

#### 简单模式（入门级）
- **算法**：贪心算法 + 随机因子
- **策略**：
  - 评估每个空位的得分（攻击分 + 防守分）
  - 选择得分最高的位置
  - 30%概率随机选择次优位置（模拟失误）
- **评估标准**：
  - 连2：10分
  - 连3：100分
  - 连4：1000分
  - 活三/活四加权更高

#### 中等模式（业余水平）
- **算法**：Minimax算法（深度2-3层）
- **策略**：
  - 预判未来2-3步的局势
  - 评估函数考虑：连子数量、活度、威胁度
  - 优先防守对方的活三、活四
- **优化**：只考虑有价值的空位（周围有棋子的位置）

#### 困难模式（中高级水平）
- **算法**：Minimax + Alpha-Beta剪枝（深度4-5层）
- **策略**：
  - 更深的搜索深度
  - 更精确的评估函数（考虑棋形、位置价值）
  - 权衡攻击与防守
- **优化技巧**：
  - 启发式搜索（优先考虑关键位置）
  - 置换表（缓存已计算的局面）
  - 迭代加深（逐步增加搜索深度）

## 7. 错误处理与边界情况

### 7.1 边界情况处理

| 场景 | 处理方式 |
|------|---------|
| 位置已被占用 | Toast提示"该位置已有棋子" |
| 游戏已结束 | 禁止落子，提示"游戏已结束" |
| 悔棋无历史 | 禁用悔棋按钮 |
| 重新开始 | 弹出确认对话框 |
| 切换模式 | 游戏中禁止，提示"请先结束当前游戏" |
| AI计算超时 | 强制返回当前最优解 |
| LocalStorage失败 | 降级为内存存储 |

### 7.2 用户提示

使用Toast轻提示，不打断用户操作：
```javascript
showToast('该位置已有棋子', 'warning')
showToast('AI思考中...', 'info')
showToast('黑方获胜！', 'success')
```
